# 按人交叉验证草案(W2 步骤 11,仅供讨论)

**这是草案,不改变当前划分。** 文档与协议 v2 都写明:本轮不切换 62 人 CV;若后续改变划分或协议,需全组统一升版并重跑相关比较。
测试集 16 人继续封存。

## 为什么要讨论

当前所有"区间"都来自同一批 8 名验证者:按人 bootstrap 区间很宽,C 的 60 组 S1-S0 配对里,Macro-F1 区间含 0 的占 92%,
N1 F1 占 83%(`reports/week2/external_C/paired_comparison.csv`)。这反映的是 8 人太少,不是方法等效。
同时 8 人已用于开发和选模,不能称独立测试。

## 草案方案

| 项 | 方案 | 说明 |
| --- | --- | --- |
| 受试者池 | 54 训练 + 8 验证 = 62 人;16 测试仍封存 | 不动测试集 |
| 折数 | 5 折按人,每折约 12–13 人做验证 | 同一人所有夜晚在同一折;可按年龄分层(沿用 A 的分层依据) |
| 预算 | 每折训练池约 49–50 人,有标签人数按池内重新取 5 / 约 13 / 约 25 / 全部 | 比例需重新约定,不能直接沿用 5/14/27/54 |
| 取人规则 | 每折在训练池内按固定种子排序后取前 k,保持嵌套;**不按验证成绩挑人** | 与现行 seed2024 排序同一原则 |
| 标准化与选模 | 每折重新拟合,只用该折有标签者;按该折验证 Macro-F1 选权重 | 同协议 v2 |
| 报告 | 先对 62 人汇总,再做按人配对区间;训练种子波动另报 | 5 折 × 5 seed 仍不是 25 个独立样本 |

## 代价(以 B 自己的格子为例)

- 现行:40 个 run(监督头 20 + 上下文 20)。5 折后约 200 个;线性头每个几十秒,上下文头为分钟级,CPU 可承受。
- A、C、D 需各自重训;C 的主干适配若按折重做,代价最大(每折每个适配 seed 一次),需 C 先评估。
- 现有 8 人上的所有结果不能直接当作某一折的结果复用(名单与池都会变)。

## 需要全组决定的事

1. 是否要升版到 protocol v3?什么时候切换(建议:W2 汇总完成之后,作为下一轮)。
2. 折内预算人数怎么约定(5 / 13 / 25 / 全部 还是别的)。
3. 是否保留当前 8 人作为"回归检查"集合,用来对照旧结果。
4. C 的适配、D 的半监督在 CV 下按折重做还是只对其中一折做先导。

在以上决定之前,B 不会生成任何新折或新名单。
