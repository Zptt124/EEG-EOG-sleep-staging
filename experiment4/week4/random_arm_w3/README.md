# 实验 D｜优先标新人，比直接随机挑块好多少？（2026-11-28）

## 结论先说

主比较是"新人新夜 − 随机"的五类 Macro-F1 差，单位为百分点（pp）。方括号是 95% 配对区间，16 位开发评估者，head seed 0。

| 窗口 | 名单 / 配对抽块 | 新人新夜 − 随机 | 名单同向 | 随机 − 原人原夜 | 随机 − 原人另一夜 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 旧窗口（调通用，C 开发复验的候选池） | 30 / 150 | **+1.48 [+0.54, +2.51]** | 22/30 | +0.05 [−0.75, +0.83] | −0.39 [−1.46, +0.61] |
| **关灯窗口（正式，C 锁定的候选池），固定尝试 600 段** | 26 / 130 | **+0.36 [−0.51, +1.26]** | 14/26 | +0.19 [−0.74, +1.08] | −0.22 [−1.18, +0.71] |
| 关灯窗口，严格等预算（新人组和随机组都拿到 600 个五类标签） | 23 / 65 | +0.14 [−0.94, +1.24] | 11/23 | +0.41 [−0.74, +1.58] | −0.47 [−1.69, +0.65] |

- 旧窗口下，"优先标新人"明显好于随机挑块，好约 1.5 pp；随机组和"原人原夜"几乎一样。
- **关灯窗口（正式比较）下，新人相对随机的优势缩小到 +0.36 pp，区间跨 0，判为不确定**。这和 C 的发现一致：在关灯窗口下，"新人新夜 − 原人原夜"也从 +1.64 降到了 +0.55（固定尝试口径）。
- 分评估队列看（关灯、固定尝试）：dev8 为 +0.42 [−0.62, +1.61]，pretrain_eval8 为 +0.42 [−0.55, +1.48]。旧窗口的两个队列分别是 +1.65 和 +1.42，区间都不含 0。全部结果在 `analysis_*/paired_summary.csv`。

## 随机组实际覆盖了什么

每次抽 10 块（600 段），下表是 5 次抽块 × 全部名单的平均值，括号里是最小值–最大值：

| 窗口 | 人数 | 夜数 | 来自原人原夜 | 来自原人另一夜 | 来自新人新夜 |
| --- | --- | --- | --- | --- | --- |
| 旧窗口 | 6.39（4–9） | 7.41（5–10） | 2.91 | 3.48 | 3.61 |
| 关灯窗口 | 6.45（4–9） | 7.52（6–10） | 2.42 | 3.91 | 3.67 |

随机组平均只有约 3.7 块来自新人，其余来自原 5 人的两夜。逐次数字见 `out_*/random_coverage.csv`。

## 抽样规则（与任务书一致）

1. 对每份名单，合并三组（原人原夜、原人另一夜、新人新夜）的合格候选块，按（记录，起始 epoch）去重，剔除与 1,200 段起点重叠的块（实际剔除 0 块，C 的候选池已经剔除过）。
2. 固定时段配额：每个夜间三分位抽的块数，等于其他三组在该时段各自追加的块数（脚本核对过三组、五次抽块的配额完全相同，合计 10 块）。
3. 每个时段内按块等概率、不放回抽取。每份名单独立抽 5 次，种子为 `random.Random(2026112901 * 100 + 名单)`（旧窗口）和 `random.Random(2026112902 * 100 + 名单)`（关灯窗口）。
4. 抽块只用记录号、epoch 号和时段，不读分期标签。抽块锁定后，才补提特征、读取标签。

## 训练与评分

- 训练 = 名单原有的 1,200 段起点 + 随机组 600 段。线性头用第一周的 trainer（`fit`，30 轮，batch 128，head seed 0），与 C 完全相同。旧窗口的名单 1–3 另跑了 seed 1、2。
- 评估 = C 开发复验的 16 人（dev8 + pretrain_eval8），样本顺序与 C 相同。三组的混淆计数直接取自 C 的归档，随机组由 D 新拟合。
- 关灯窗口里缓存没有的 4,290 段，按 C 的提取流程补提特征：从 PhysioNet 下载 57 条记录并校验 SHA-256，用 W4 30k EMA 的第 10–12 层、1 秒 std 池化。与缓存重叠的段，标签全部一致，特征重放误差最大 2e-4。无法评分的段屏蔽，不替换。
- 区间沿用 C 的重抽样方式：名单有放回抽样，名单内抽块有放回抽样，两个 8 人评估队列内按 multinomial 加权，共 10,000 次，`default_rng(0)`。

## 自查

- 拟合流程对齐：重拟 C 的头（旧窗口名单 1 第 1 次新人组；关灯窗口名单 1 第 1 次新人组），16×25 混淆计数与 C 的归档逐格相同。
- 统计对齐：用同一个 `macro` 实现重算 C 自己报告的"新人新夜 − 原人原夜"，旧窗口 +1.5265、关灯窗口 +0.5458（固定尝试）和 +0.2414（严格等预算），与 C 的数字一致到 1e-12。
- seed 敏感性（旧窗口名单 1–3，新人 − 随机）：seed 0/1/2 分别为 +0.81 / +1.39 / +1.15。

## 注意

- 关灯窗口"严格等预算"口径的定义：新人组和随机组都拿到 600 个标签（65 对）。C 的定义要求三组都拿到（43 对），两者不同。
- 开发评估的 16 人里，dev8 已经反复用于开发，另外 8 人参加过骨干的无标签预训练。预留 8 人和最终封存的 16 人都没有使用。
- 名单之间会共享个体，区间以现有训练池和这些名单为条件。
